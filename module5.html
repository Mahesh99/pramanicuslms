Section 5.1

What is Object-Oriented Programming?

OOP is a programming paradigm that organises code around objects — bundles that combine data (attributes) and behaviour (methods) into a single unit. Rather than writing separate functions that manipulate data, you create objects that know both what they are and what they can do.

Analogy: A Car A car has attributes (colour, model, fuel level, speed) and methods (start(), accelerate(), brake(), refuel()). The car's internal engine mechanics are hidden — you just press the pedal. This is OOP.

Four Pillars of OOP

🔒 Encapsulation

Bundle data and methods together; hide internal details. Only expose what's needed.

👨‍👦 Inheritance

A child class inherits attributes and methods from a parent class, then extends or overrides them.

🎭 Polymorphism

Different objects respond to the same method call in their own way. One interface, many behaviours.

🎭 Abstraction

Hide complex implementation details. Show only the necessary interface to the outside world.

Section 5.2

Classes & Objects

A class is a blueprint (template). An object (or instance) is a specific thing created from that blueprint. You can create many objects from one class.

Analogy: A class is like an architectural drawing for a house. Each actual house built from that drawing is an object (instance). All houses have the same structure, but different colours, sizes, and owners.
Defining a class and creating objects
class Dog:
    # Class variable — shared by ALL instances
    species = "Canis lupus familiaris"

    # Instance method — self refers to the specific object
    def __init__(self, name, breed, age):
        # Instance variables — unique to each object
        self.name  = name
        self.breed = breed
        self.age   = age

    def bark(self):
        return f"{self.name} says: Woof!"

    def describe(self):
        return f"{self.name} is a {self.age}-year-old {self.breed}"

# Create instances (objects)
rex   = Dog("Rex", "Labrador", 3)
buddy = Dog("Buddy", "Poodle", 1)

# Access attributes and methods
print(rex.name)          # "Rex"
print(rex.bark())        # "Rex says: Woof!"
print(buddy.describe()) # "Buddy is a 1-year-old Poodle"

# Class variable accessible on class or instance
print(Dog.species)      # "Canis lupus familiaris"
print(rex.species)      # same

Instance Variables vs Class Variables

Instance VariableClass Variable
DefinedInside __init__ using self.xAt class level, outside any method
ScopeBelongs to one specific objectShared by all instances
Use caseAttributes that differ per object (name, age)Attributes common to all (species, tax_rate)

Section 5.3

__init__ & self Explained

__init__ — The Constructor

__init__ is a special method automatically called when you create a new object. Its purpose is to initialise the object's attributes. Think of it as "setting up the new object".

self — Reference to the Current Object

self is a reference to the specific instance that the method is operating on. It must be the first parameter of every instance method, but Python passes it automatically — you never provide it when calling.

Understanding self
class Counter:
    def __init__(self, start=0):
        self.value = start   # self.value is an instance variable

    def increment(self):
        self.value += 1    # self refers to THIS specific counter

    def reset(self):
        self.value = 0

c1 = Counter()
c2 = Counter(10)

c1.increment()
c1.increment()
print(c1.value)   # 2   — c1 and c2 are independent
print(c2.value)   # 10  — unchanged

# When you call c1.increment(), Python translates it to:
# Counter.increment(c1)  ← self IS c1

Section 5.4

Encapsulation

Encapsulation means bundling data and methods together and restricting direct access to some attributes. You expose a controlled interface instead of raw data.

ConventionPrefixBehaviour
PublicNo prefix: self.nameAccessible from anywhere
ProtectedSingle underscore: self._salaryConvention: "internal use". Can still be accessed, but signals "don't touch unless you know what you're doing"
PrivateDouble underscore: self.__pinName-mangled to _ClassName__pin. Hard (but not impossible) to access from outside
Bank account with encapsulation
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner      = owner        # public
        self._bank_name = "PramanicusBank"  # protected
        self.__balance  = balance      # private
        self.__pin      = 1234        # private

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("Deposit amount must be positive")
        self.__balance += amount
        print(f"Deposited ₹{amount}. New balance: ₹{self.__balance}")

    def withdraw(self, amount, pin):
        if pin != self.__pin:
            print("Wrong PIN!")
            return
        if amount > self.__balance:
            print("Insufficient funds")
            return
        self.__balance -= amount

    def get_balance(self):
        return self.__balance   # controlled read access

acc = BankAccount("Alice", 1000)
acc.deposit(500)
print(acc.get_balance())      # 1500
# print(acc.__balance)        ← AttributeError
# print(acc._BankAccount__balance)  ← works (name mangling)

Section 5.5

Inheritance & MRO

Inheritance allows a class to inherit attributes and methods from a parent class. The child class gets everything the parent has, and can add or override behaviour.

Single inheritance
class Animal:
    def __init__(self, name, age):
        self.name = name
        self.age  = age

    def breathe(self):
        return f"{self.name} breathes air"

    def speak(self):
        return "..."   # default — will be overridden


class Dog(Animal):                 # Dog inherits from Animal
    def __init__(self, name, age, breed):
        super().__init__(name, age)  # call parent's __init__
        self.breed = breed           # add new attribute

    def speak(self):                 # override parent method
        return "Woof!"

    def fetch(self):                 # new method specific to Dog
        return f"{self.name} fetches the ball!"


class Cat(Animal):
    def speak(self):
        return "Meow!"


d = Dog("Rex", 3, "Labrador")
print(d.breathe())   # inherited from Animal
print(d.speak())     # overridden → "Woof!"
print(d.fetch())     # Dog-specific method

# isinstance() checks the entire inheritance chain
print(isinstance(d, Dog))    # True
print(isinstance(d, Animal)) # True! — Dog IS an Animal
print(issubclass(Dog, Animal)) # True

Multiple Inheritance & MRO

Multiple inheritance and MRO
class Flyable:
    def fly(self):
        return "Flying!"

class Swimmable:
    def swim(self):
        return "Swimming!"

class Duck(Animal, Flyable, Swimmable):
    def speak(self):
        return "Quack!"

donald = Duck("Donald", 5)
print(donald.fly())    # "Flying!"
print(donald.swim())   # "Swimming!"
print(donald.speak())  # "Quack!"

# Method Resolution Order (MRO) — how Python decides which method to call
print(Duck.__mro__)
# (<class 'Duck'>, <class 'Animal'>, <class 'Flyable'>,
#  <class 'Swimmable'>, <class 'object'>)
💡
Always call super().__init__() in child classes that override __init__. This ensures the parent class is properly initialised. super() follows the MRO to find the right parent.

Section 5.6

Polymorphism

Polymorphism means "many forms". The same method name behaves differently depending on which object it's called on. This lets you write code that works with objects of different types through a common interface.

Polymorphism — method overriding
class Shape:
    def area(self):
        return 0

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        import math
        return math.pi * self.r ** 2

class Rectangle(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h
    def area(self):
        return self.w * self.h

class Triangle(Shape):
    def __init__(self, b, h):
        self.b, self.h = b, h
    def area(self):
        return 0.5 * self.b * self.h

# Polymorphism in action — same method name, different behaviour
shapes = [Circle(5), Rectangle(4, 6), Triangle(3, 8)]

for shape in shapes:
    print(f"{type(shape).__name__} area: {shape.area():.2f}")
# Circle area: 78.54
# Rectangle area: 24.00
# Triangle area: 12.00

Duck Typing

Python's polymorphism is based on duck typing: "If it walks like a duck and quacks like a duck, it IS a duck." Python doesn't care what type an object is — only whether it has the method you're calling.

Duck typing
class Dog:
    def speak(self): return "Woof!"

class Cat:
    def speak(self): return "Meow!"

class Robot:              # NOT related to Dog or Cat at all
    def speak(self): return "Beep boop!"

def make_speak(thing):   # doesn't care about type — just needs .speak()
    print(thing.speak())

for obj in [Dog(), Cat(), Robot()]:
    make_speak(obj)
# Woof!  Meow!  Beep boop!

Section 5.7

Abstraction — Abstract Base Classes

An abstract class defines a contract — a set of methods that all subclasses must implement. You cannot instantiate an abstract class directly. This enforces a consistent interface across all subclasses.

Abstract base class with abc module
from abc import ABC, abstractmethod

class Shape(ABC):              # inherit from ABC
    @abstractmethod
    def area(self):
        pass                    # no implementation here

    @abstractmethod
    def perimeter(self):
        pass

    def describe(self):         # non-abstract: has implementation
        return f"Area: {self.area():.2f}, Perimeter: {self.perimeter():.2f}"

# s = Shape()   ← TypeError: Can't instantiate abstract class

class Circle(Shape):
    def __init__(self, r):
        self.r = r
    def area(self):
        import math; return math.pi * self.r**2
    def perimeter(self):
        import math; return 2 * math.pi * self.r

c = Circle(5)
print(c.describe())

Section 5.8

Magic / Dunder Methods

Magic methods (also called dunder methods — "double underscore") are special methods Python calls automatically in response to built-in operations. They let you define how your class responds to operators, built-in functions, and language features.

MethodTriggered byUse case
__init__MyClass()Constructor / initialise attributes
__str__str(obj), print(obj)Human-readable string representation
__repr__repr(obj), REPL outputDeveloper/debug representation
__len__len(obj)Return "size" of the object
__eq__obj == otherEquality comparison
__lt__obj < otherLess-than comparison
__add__obj + otherAddition operator
__contains__item in objMembership test
__getitem__obj[key]Indexing / subscript
__enter__ / __exit__with statementContext manager protocol
2D Vector with magic methods
import math

class Vector2D:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __str__(self):
        return f"Vector({self.x}, {self.y})"

    def __repr__(self):
        return f"Vector2D(x={self.x}, y={self.y})"

    def __add__(self, other):
        return Vector2D(self.x + other.x, self.y + other.y)

    def __sub__(self, other):
        return Vector2D(self.x - other.x, self.y - other.y)

    def __mul__(self, scalar):
        return Vector2D(self.x * scalar, self.y * scalar)

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __abs__(self):          # magnitude
        return math.sqrt(self.x**2 + self.y**2)

    def __len__(self):
        return 2                 # always 2D

v1 = Vector2D(1, 2)
v2 = Vector2D(3, 4)

print(v1 + v2)       # Vector(4, 6)   — uses __add__
print(v1 * 3)        # Vector(3, 6)   — uses __mul__
print(v1 == v2)      # False          — uses __eq__
print(abs(v2))       # 5.0            — uses __abs__
print(len(v1))       # 2              — uses __len__
print(v1)            # Vector(1, 2)   — uses __str__

Section 5.9

@property, @classmethod, @staticmethod

@property — Computed Attributes

Makes a method accessible like an attribute. Allows getter, setter, and deleter logic.

@property
class Circle:
    def __init__(self, radius):
        self._radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value < 0:
            raise ValueError("Radius cannot be negative")
        self._radius = value

    @property
    def area(self):            # computed — no setter needed
        import math
        return math.pi * self._radius**2

c = Circle(5)
print(c.radius)     # 5         — calls getter
print(c.area)       # 78.54...  — computed property
c.radius = 10      # calls setter
# c.radius = -1    ← ValueError

@classmethod — Alternative Constructors

@classmethod
class Date:
    def __init__(self, day, month, year):
        self.day, self.month, self.year = day, month, year

    @classmethod
    def from_string(cls, date_str):
        # "dd-mm-yyyy" → Date object
        day, month, year = map(int, date_str.split("-"))
        return cls(day, month, year)  # cls is the class itself

    def __str__(self):
        return f"{self.day}/{self.month}/{self.year}"

d = Date.from_string("04-07-2026")
print(d)   # 4/7/2026

@staticmethod — Utility Methods

@staticmethod
class MathUtils:
    @staticmethod
    def is_even(n):
        return n % 2 == 0

    @staticmethod
    def clamp(value, min_val, max_val):
        return max(min_val, min(max_val, value))

print(MathUtils.is_even(4))          # True
print(MathUtils.clamp(15, 0, 10))   # 10
DecoratorFirst paramAccessesCommon use
@propertyselfInstance & classComputed attribute, validation on set
@classmethodclsClass onlyAlternative constructors, factory methods
@staticmethodNeitherNothing (pure function)Utility functions logically grouped with class
