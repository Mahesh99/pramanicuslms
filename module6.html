Section 6.1

Errors vs Exceptions

🚫 Syntax Error

Code is incorrectly written. Python detects it before running. Cannot be caught with try/except. Fix the code.

💥 Exception

Code is syntactically correct but something goes wrong at runtime. Can be caught and handled gracefully.

Syntax error vs exception
# SYNTAX ERROR — detected before running
if True           # SyntaxError: expected ':' at end
    print("hi")

# RUNTIME EXCEPTIONS — happen while running
print(10 / 0)             # ZeroDivisionError
print(int("hello"))       # ValueError
print(undefined_var)      # NameError
print([1,2,3][10])       # IndexError
print({"a":1}["b"])       # KeyError
print("hello" + 5)        # TypeError
open("nofile.txt")       # FileNotFoundError

Section 6.2

Exception Hierarchy

Python exceptions form an inheritance hierarchy. Catching a parent exception also catches all its children.

Key exceptions (simplified hierarchy)
BaseException
├── SystemExit          # raised by sys.exit()
├── KeyboardInterrupt   # Ctrl+C
└── Exception           # ← catch this for normal error handling
    ├── ArithmeticError
    │   ├── ZeroDivisionError
    │   └── OverflowError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── ValueError
    ├── TypeError
    ├── NameError
    ├── OSError
    │   ├── FileNotFoundError
    │   └── PermissionError
    └── RuntimeError
        └── RecursionError
⚠️
Never use bare except:. It catches everything including SystemExit and KeyboardInterrupt, making it impossible to stop your program. Use except Exception: at minimum, or better yet, catch specific exceptions.

Section 6.3

try / except / else / finally

Full Structure

try/except/else/finally
try:
    # Code that might raise an exception
    result = 10 / int(input("Enter divisor: "))

except ZeroDivisionError:
    # Handle specific exception
    print("Cannot divide by zero!")

except ValueError as e:
    # 'e' holds the exception object
    print(f"Invalid input: {e}")

except (TypeError, OverflowError):
    # Handle multiple exceptions in one clause
    print("Type or overflow error")

except Exception as e:
    # Catch-all for unexpected errors (log them, don't silently ignore)
    print(f"Unexpected error: {type(e).__name__}: {e}")

else:
    # Runs ONLY if no exception was raised
    print(f"Result: {result}")

finally:
    # ALWAYS runs — exception or not
    # Use for cleanup: closing files, releasing resources
    print("Execution complete.")

When Does Each Block Run?

BlockRuns when…
tryAlways (it's the guarded code)
exceptOnly if a matching exception was raised in try
elseOnly if try completed without any exception
finallyAlways — whether there was an exception or not

Practical Pattern — Safe Integer Input

Robust input validation
def get_integer(prompt, min_val=None, max_val=None):
    """Keep asking until the user enters a valid integer in range."""
    while True:
        try:
            value = int(input(prompt))
            if min_val is not None and value < min_val:
                raise ValueError(f"Must be at least {min_val}")
            if max_val is not None and value > max_val:
                raise ValueError(f"Must be at most {max_val}")
            return value
        except ValueError as e:
            print(f"Invalid: {e}. Try again.")

age = get_integer("Enter age: ", min_val=1, max_val=120)

Section 6.4

Raising Exceptions

raise statement
# raise ExceptionClass("message")
def set_age(age):
    if not isinstance(age, int):
        raise TypeError(f"Age must be an int, got {type(age).__name__}")
    if age < 0 or age > 150:
        raise ValueError(f"Age {age} is out of valid range (0-150)")
    return age

# Re-raise inside except — preserve original traceback
try:
    risky_operation()
except ValueError:
    print("Logging the error...")
    raise   # re-raise the same exception

# Exception chaining — show original cause
try:
    value = int("abc")
except ValueError as e:
    raise RuntimeError("Failed to parse config") from e

Section 6.5

Custom Exception Classes

Create custom exceptions when you want to distinguish your domain-specific errors from generic ones. They make error handling clearer and more meaningful.

Custom exception hierarchy
# Base exception for the whole application
class BankError(Exception):
    """Base class for all bank-related errors."""
    pass

class InsufficientFundsError(BankError):
    def __init__(self, amount, balance):
        self.amount  = amount
        self.balance = balance
        super().__init__(
            f"Cannot withdraw ₹{amount}; "
            f"available balance is ₹{balance}"
        )

class AccountLockedError(BankError):
    """Raised when a locked account is accessed."""
    pass

# Using custom exceptions
def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(amount, balance)
    return balance - amount

try:
    withdraw(500, 1000)
except InsufficientFundsError as e:
    print(f"Error: {e}")
    print(f"You are ₹{e.amount - e.balance} short")
except BankError as e:
    print(f"General bank error: {e}")

Section 6.6

File Handling

The with Context Manager

Always use with open(...) to work with files. It automatically closes the file when the block ends — even if an exception occurs. Never call open() without with.

Reading files
# Read entire file as one string
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()
    print(content)

# Read all lines as a list
with open("data.txt") as f:
    lines = f.readlines()         # ['line1\n', 'line2\n', ...]
    lines = [l.strip() for l in lines]  # strip whitespace

# Read line by line — memory efficient for large files
with open("data.txt") as f:
    for line in f:
        print(line.strip())

# Read one line at a time
with open("data.txt") as f:
    first_line = f.readline()
Writing files
# Write — creates file if not exists, overwrites if exists
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("Hello, World!\n")
    f.write("Second line\n")
    f.writelines(["line3\n", "line4\n"])

# Append — adds to end of file
with open("log.txt", "a") as f:
    f.write("New log entry\n")
ModeDescriptionFile must exist?
"r"Read only (default)Yes — FileNotFoundError if not
"w"Write — creates or truncatesNo — creates if not exists
"a"Append — creates or appendsNo — creates if not exists
"r+"Read and writeYes
"x"Create new — fails if existsNo — raises FileExistsError if it does
"b"Binary mode (add to any above)—

Handle File Errors Gracefully

File exception handling
def read_file_safe(filepath):
    try:
        with open(filepath, encoding="utf-8") as f:
            return f.read()
    except FileNotFoundError:
        print(f"File not found: {filepath}")
        return None
    except PermissionError:
        print(f"No permission to read: {filepath}")
        return None
    except UnicodeDecodeError:
        print("File encoding issue — try encoding='latin-1'")
        return None

Section 6.7

CSV Files

CSV (Comma-Separated Values) is the most common format for tabular data. Python's built-in csv module handles reading and writing correctly (including quoted fields with commas).

Reading CSV
import csv

# Read as a list of rows (each row is a list)
with open("students.csv", newline="") as f:
    reader = csv.reader(f)
    header = next(reader)   # skip header row
    for row in reader:
        print(row)           # ['Alice', '20', '88']

# Read as list of dicts — each row is {header: value}
with open("students.csv", newline="") as f:
    reader = csv.DictReader(f)
    students = list(reader)   # list of OrderedDict

for s in students:
    print(s["name"], s["score"])
Writing CSV
import csv

students = [
    {"name": "Alice", "age": 20, "score": 88},
    {"name": "Bob",   "age": 22, "score": 72},
]

with open("output.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.DictWriter(f, fieldnames=["name", "age", "score"])
    writer.writeheader()
    writer.writerows(students)   # write all at once
💡
Always pass newline="" when opening CSV files. Without it, you may get extra blank lines on Windows, because csv.writer handles its own line endings.

Section 6.8

JSON Files

JSON (JavaScript Object Notation) is a universal data exchange format. Python dicts map naturally to JSON objects; lists map to JSON arrays.

JSON read and write
import json

# Python dict / list ↔ JSON string
data = {
    "name":    "Alice",
    "scores":  [88, 92, 95],
    "active":  True,
    "address": None
}

# Serialize: Python → JSON string
json_str = json.dumps(data, indent=2)
print(json_str)

# Deserialize: JSON string → Python
loaded = json.loads(json_str)
print(loaded["name"])   # "Alice"

# Write to file
with open("data.json", "w") as f:
    json.dump(data, f, indent=2)

# Read from file
with open("data.json") as f:
    loaded = json.load(f)

print(loaded["scores"])  # [88, 92, 95]
FunctionDirectionWith/Without file
json.dumps(obj)Python → JSON stringWithout file (in-memory)
json.loads(string)JSON string → PythonWithout file
json.dump(obj, file)Python → JSON fileWith file
json.load(file)JSON file → PythonWith file

Section 6.9

File Paths with pathlib

pathlib.Path is the modern, object-oriented way to work with file paths. It handles OS differences (Windows \ vs Unix /) automatically.

pathlib.Path
from pathlib import Path

# Create a Path object
p = Path("data") / "students.csv"   # / operator joins paths

# Path properties
print(p)              # data/students.csv (or data\students.csv on Windows)
print(p.name)         # students.csv
print(p.stem)         # students
print(p.suffix)       # .csv
print(p.parent)       # data
print(p.resolve())    # absolute path

# Check existence
print(p.exists())     # True/False
print(p.is_file())    # True if it's a file
print(p.is_dir())     # True if it's a directory

# Read and write with Path
text = p.read_text(encoding="utf-8")   # read entire file
p.write_text("content")                  # write (replaces)

# Create directories
Path("output/data").mkdir(parents=True, exist_ok=True)

# List all CSV files in a directory
for f in Path(".").glob("*.csv"):
    print(f.name)

# Recursively find all .py files
for f in Path(".").rglob("*.py"):
    print(f)
✅
Use pathlib, not string concatenation. Path("data") / "file.csv" is safer and clearer than "data" + "/" + "file.csv", which breaks on Windows.
